Why this API

Built for orbit-tracking clients, not for scraping

The upstream sites are excellent and human-shaped. This service keeps their data intact and makes it machine-shaped: stable paths, stable envelopes, honest cache headers.

Merged TLE feed

All upstream groups are de-duplicated by NORAD catalogue number, with the freshest epoch winning and the losing source recorded in meta.sources.

GET /v1/tle

Per-source endpoints

Need only one upstream? /v1/tle/weather, /v1/tle/amateur, /v1/tle/amsat and /v1/tle/satnogs return that source untouched by the merge.

GET /v1/tle/{source}

JSON or classic 20-column TLE

Content negotiation, not a second API. Send Accept: text/plain or ?format=tle for two-line elements your existing tracker already parses.

Accept: application/json | text/plain

Edge-cached with ETag

Strong ETags, Cache-Control with stale-while-revalidate, and 304 responses so pollers cost almost nothing when the elements have not changed.

ETag · If-None-Match · SWR

SatNOGS catalogue

Satellites and transmitters with limit/offset pagination, field projection via fields=, and filters such as norad, mode and status.

GET /v1/satellites · /v1/transmitters

Predictable errors and a real spec

Every failure is RFC 9457 application/problem+json with a stable type URI, and the whole surface is described by an OpenAPI 3.1 document.

problem+json · OpenAPI 3.1

Public endpoints

All routes are GET, unauthenticated and rate limited generously. TTLs are the edge cache lifetime for a warm entry; the first request after expiry revalidates upstream.

Method, path, purpose and cache TTL for the v1 surface.
Method Path Description Cache TTL
GET /v1/tle Merged, de-duplicated TLE feed from every upstream source. 3 h
GET /v1/tle/{source} Single source: weather, amateur, amsat, satnogs or merged. 3 h
GET /v1/satellites SatNOGS satellite catalogue with pagination and field projection. 12 h
GET /v1/transmitters SatNOGS transmitter records, filterable by satellite, mode and status. 6 h
GET /v1/amsat/status AMSAT status report feed for active amateur satellites. 6 h
GET /v1/health Liveness probe for the API process and its Redis cache. 10 s
GET /v1/status Public status document, including per-upstream freshness. 60 s
GET /v1/meta Service version, build metadata and the upstream source list. 5 min
GET /v1/maintenance Current and scheduled maintenance windows, plus cache purge notices. 10 min

Deprecated The pre-v1 aliases /tle, /tle/{source} and /health still answer, but they return a Deprecation and Sunset header and are scheduled for removal. New clients should use the /v1 paths above.

Quickstart

Four requests, no SDK

Every sample below hits the live service. The base URL is https://satellite.api.authskin.xyz and no key or header is required.

shell · merged feed and one satellite 
# 1. Merged feed — every upstream source, de-duplicated
curl -sS -H 'Accept: application/json' \
  'https://satellite.api.authskin.xyz/v1/tle' | jq '.meta.count, .data[0].name'

# 2. One satellite, JSON envelope (ISS, NORAD 25544)
curl -sS 'https://satellite.api.authskin.xyz/v1/tle/weather?norad=25544&format=json'

# 3. Same satellite as classic 20-column TLE lines
curl -sS -H 'Accept: text/plain' \
  'https://satellite.api.authskin.xyz/v1/tle/weather?norad=25544&format=tle'

# 4. Health probe, the same one the status pill uses
curl -sS 'https://satellite.api.authskin.xyz/v1/health'
javascript · browser or Node 18+ 
var BASE = 'https://satellite.api.authskin.xyz';

// Merged feed, then one satellite from a single upstream.
fetch(BASE + '/v1/tle', { headers: { Accept: 'application/json' } })
  .then(function (res) {
    if (!res.ok) throw new Error('HTTP ' + res.status);
    return res.json();
  })
  .then(function (envelope) {
    console.log(envelope.meta.count + ' satellites merged');
    return fetch(BASE + '/v1/tle/weather?norad=25544&format=json');
  })
  .then(function (res) { return res.json(); })
  .then(function (envelope) {
    var iss = envelope.data[0];
    console.log(iss.name, iss.epoch);
    console.log(iss.line1);
    console.log(iss.line2);
  })
  .catch(function (err) { console.error('request failed:', err.message); });
python · requests 
import requests

BASE = "https://satellite.api.authskin.xyz"

# Merged feed — everything, de-duplicated.
merged = requests.get(BASE + "/v1/tle", timeout=10).json()
print(merged["meta"]["count"], "satellites merged from", merged["meta"]["sources"])

# One satellite, JSON envelope.
iss = requests.get(
    BASE + "/v1/tle/weather",
    params={"norad": 25544, "format": "json"},
    timeout=10,
).json()

sat = iss["data"][0]
print(sat["name"], sat["norad_id"], sat["epoch"])
print(sat["line1"])
print(sat["line2"])
php · curl 
<?php
$base = 'https://satellite.api.authskin.xyz';

// Merged feed.
$ch = curl_init($base . '/v1/tle');
curl_setopt_array($ch, array(
    CURLOPT_RETURNTRANSFER => true,
    CURLOPT_HTTPHEADER     => array('Accept: application/json'),
    CURLOPT_TIMEOUT        => 10,
));
$merged = json_decode(curl_exec($ch), true);
curl_close($ch);

printf("%d satellites merged\n", $merged['meta']['count']);

// One satellite: ISS, NORAD 25544.
$ch = curl_init($base . '/v1/tle/weather?norad=25544&format=json');
curl_setopt_array($ch, array(
    CURLOPT_RETURNTRANSFER => true,
    CURLOPT_HTTPHEADER     => array('Accept: application/json'),
    CURLOPT_TIMEOUT        => 10,
));
$payload = json_decode(curl_exec($ch), true);
curl_close($ch);

$sat = $payload['data'][0];
echo $sat['name'], ' ', $sat['norad_id'], PHP_EOL;
echo $sat['line1'], PHP_EOL, $sat['line2'], PHP_EOL;

Response envelope

Every successful /v1/* response uses the same shape: a meta block describing the request and its cache state, and a data array of records.

200 OK · application/json · GET /v1/tle/weather?norad=25544&format=json 
{
  "meta": {
    "service": "satellite-data-api",
    "version": "v3.3.0+ra",
    "api_version": "v1",
    "generated": "2026-09-15T21:20:04Z",
    "request_id": "0f2c1b7a-5d3e-4f1a-9c88-1b2f4e6a7d10",
    "count": 1,
    "cache": {
      "hit": true,
      "key": "tle:weather:25544:json",
      "ttl": 10800,
      "age": 412
    }
  },
  "data": [
    {
      "norad_id": 25544,
      "name": "ISS (ZARYA)",
      "epoch": "2026-09-15T21:14:23Z",
      "source": "celestrak:weather",
      "line1": "1 25544U 98067A   26258.88499338  .00006292  00000-0  12172-3 0  9990",
      "line2": "2 25544  51.6310 211.2092 0004923 144.3133 215.8185 15.49128922585812"
    }
  ]
}

Errors replace data with RFC 9457 problem details, for example {"type":"https://satellite.api.authskin.xyz/problems/norad-not-found","title":"Satellite not found","status":404,"detail":"...","instance":"/v1/tle/weather","request_id":"..."}.

Attribution

The data belongs to the upstream providers

This service only fetches, normalises, de-duplicates and caches. If you publish derived work, credit the sources below and follow their terms — not this API’s.

weather · amateur

CelesTrak

Authoritative TLE groups maintained by Dr. T.S. Kelso, including the weather and amateur sets merged into /v1/tle/weather and /v1/tle/amateur.

https://celestrak.org

status reports

AMSAT

Amateur satellite status and reporting, surfaced through /v1/amsat/status alongside the AMSAT TLE set.

https://www.amsat.org
